# gs2print

macOS and Windows app that acts as a virtual ImageWriter II printer, including acting as a print server on a network.

It converts ImageWriter print data into a page preview and a PDF.

It can:
1. Open a raw dump file
2. Listen on a network port
3. be opened by GSSquared and talk to it directly

## Requirements

- **Windows:** Windows 10 version 1903 (May 2019 Update) or later, 64-bit (x64). Windows 11 works. `gs2print.exe` is a single file and needs no installer, runtime, or redistributable; copy it anywhere and run it. The first run registers `.gs2print` for the current user.
- **macOS:** macOS 26 or later.

## Install

### MacOS

Unpack the program. Then:
```
xattr -d com.apple.quarantine gs2print.app
```

Run it at least once to register the .gs2print file type with MacOS.

### Windows

Unpack the program. Run it at least once to register the .gs2print file type with Windows.


## Using with a Raw dump file

If you have a raw dump of a byte stream generated by a program and intended for an ImageWriter, you can File > Open directly with gs2print. 

## Using with Emulators

### GSSquared

There are two ways to use gs2print with GSSquared.

1. GSSquared talks to gs2print mainly by creating a "Ticket" file named "something.gs2print", then asking the operating system to open that file. As long as you have run gs2print once before, it will be registered with your operating system. When a program inside GSSquared starts sending data to the printer, GSSquared will fire up gs2print, then gs2print will open a connection back to GSSquared for the print session. This works only on the local machine of course, but provides tight integration with GSSquared.

2. GSSquared also allows entering arbitrary IP:Port and then you can use it like with KEGS below to a print server on any machine on your network.

### KEGS

KEGS lets you specify a network IP address and port for outbound serial port connections to go to. This seems to work fine by specifying either 127.0.0.1:9100 or IP.AD.DR.ESS:9100. The port is arbitrary and can be set in gs2print Settings.

I did notice however that if KEGS can't connect to the port when it tries right after you set the values, that it does not seem to retry automatically and you have to go back to F4 Serial Port setup and modify it again to get it to connect.

## Using with Real Hardware

You will need some serial-to-network device that can create a RAW TCP socket to an IP and Port. I don't know much about these, but I know they exist.

## Build

The decoder and page bitmap live in `core/`. The SwiftUI window in `app/` only displays that bitmap and calls the C API in `core/include/gs2print.h`. PDF pages are written with the vendored copy of [libHaru](https://github.com/libharu/libharu).

### MacOS

Requires Xcode with the macOS 15 SDK. zlib is the system library; nothing else is fetched at build time.

Open `gs2print.xcodeproj` and run the **gs2print** scheme.

From the command line:

```sh
xcodebuild -project gs2print.xcodeproj -scheme gs2print -configuration Debug -derivedDataPath build
open build/Build/Products/Debug/gs2print.app
```

The **gs2print_tests** scheme is a small command-line driver, not an XCTest bundle:

```sh
xcodebuild -project gs2print.xcodeproj -scheme gs2print_tests -configuration Debug -derivedDataPath build
./build/Build/Products/Debug/gs2print_tests
```

`build/` and Xcode’s `DerivedData/` are gitignored.

### Windows

On Windows, install Build Tools for Visual Studio 2022 with the C++ workload, CMake, and Ninja. The Visual Studio IDE is not required. From the repo root:

```powershell
.\build.ps1
```

That builds `build\gs2print.exe` and runs `build\gs2print_tests.exe`. See [WindowsBuild.md](WindowsBuild.md).
